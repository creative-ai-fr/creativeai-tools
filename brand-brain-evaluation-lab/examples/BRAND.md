# Lumen Commons — Brand Brain de démonstration

> Exemple fictif destiné aux tests du Brand Brain Evaluation Lab. Aucun nom, logo, chiffre ou asset réel ne doit être déduit de ce document.

## 1. Posture et positionnement

Lumen Commons aide les petites équipes à rendre leurs projets d’IA compréhensibles, vérifiables et utilisables.

### Public prioritaire

Équipes produit et communication de 3 à 30 personnes qui utilisent déjà des assistants IA mais ne disposent pas d’un système clair de sources, de règles et de validation.

### Problème traité

Les équipes produisent plus vite, mais leurs contenus deviennent génériques, leurs sources se mélangent et personne ne sait clairement quand un humain doit arbitrer.

### Promesse

Lumen Commons aide une équipe à transformer ses décisions de marque en règles consultables et testables.

### Différence

Lumen Commons explique les décisions et leurs limites. Il ne promet ni automatisation complète, ni conformité juridique automatique, ni résultat business garanti.

### Sujets légitimes

- structuration de connaissances de marque ;
- évaluation d’assistants IA ;
- gouvernance éditoriale ;
- provenance des sources ;
- validation humaine ;
- formats Markdown, JSON et YAML.

### Sujets à traiter avec prudence

- sécurité juridique ;
- performance commerciale ;
- santé, finance ou réglementation ;
- comparaison de modèles sans protocole équivalent ;
- affirmation de supériorité technique.

## 2. Publics et situations

| Public | Situation | Blocage | Niveau de connaissance |
|---|---|---|---|
| Responsable communication | Doit produire une campagne cohérente avec peu de temps | Les règles sont dispersées | intermédiaire |
| Fondateur | Veut savoir si l’IA dilue sa marque | Ne sait pas quoi mesurer | débutant à intermédiaire |
| Responsable produit | Doit documenter une fonctionnalité IA | Les affirmations sont difficiles à prouver | intermédiaire |
| Contributeur open source | Veut réutiliser les règles dans son outil | Le format propriétaire bloque l’usage | avancé |

## 3. Voix et style

### Identité

Lumen Commons parle comme un praticien calme qui rend les décisions plus faciles à examiner.

### Qualités

- précis ;
- pédagogique ;
- concret ;
- nuancé ;
- ouvert aux contributions.

### Règles de style

## RULE-VOICE-001 — Expliquer avant de convaincre

| Champ | Valeur |
|---|---|
| Type | éditoriale |
| Périmètre | articles, posts, documentation |
| Priorité | obligatoire |
| Statut | active |
| Source | DEC-001 |

Présenter le problème ou la décision avant la promesse.

**Exemple :** “Une note élevée peut masquer une invention de preuve. Le score doit donc être accompagné de contrôles bloquants.”

**Contre-exemple :** “La méthode ultime pour rendre votre IA parfaitement fiable.”

**Contrôle :** le lecteur comprend-il le problème avant de recevoir la promesse ?

## RULE-VOICE-002 — Préférer les formulations vérifiables

| Champ | Valeur |
|---|---|
| Type | éditoriale |
| Périmètre | tous les canaux |
| Priorité | obligatoire |
| Statut | active |
| Source | DEC-002 |

Employer des verbes observables : mesurer, comparer, vérifier, documenter, signaler, escalader.

**À privilégier :** “Le protocole rend les conditions de comparaison visibles.”

**À éviter :** “Le protocole garantit une IA fiable.”

## RULE-VOICE-003 — Ne pas utiliser le jargon comme preuve

| Champ | Valeur |
|---|---|
| Type | vocabulaire |
| Périmètre | contenus destinés aux équipes non techniques |
| Priorité | recommandé |
| Statut | active |
| Source | DEC-003 |

Expliquer un terme technique à sa première occurrence ou employer un équivalent courant.

## Mots et formulations à éviter

- révolutionnaire ;
- garanti ;
- zéro risque ;
- parfaitement fiable ;
- remplace l’humain ;
- la meilleure solution ;
- conforme par défaut.

## 4. Territoires et formats

| Territoire | Rôle | Formats adaptés |
|---|---|---|
| Rendre la marque lisible | expliquer les six couches | article, guide, atelier |
| Tester plutôt que supposer | montrer les évaluations | étude de cas, tableau, démonstration |
| Documenter les limites | rendre les arbitrages visibles | checklist, journal de décision |
| Ouvrir les méthodes | favoriser la réutilisation | dépôt Git, modèle, tutoriel |

## 5. Invariants visuels

Pour les supports de démonstration :

- fond clair ou graphite, jamais de dégradé décoratif dominant ;
- une couleur d’accent jaune-lumen utilisée pour signaler une décision ou une alerte ;
- typographie sans empattement, lisible, avec une hiérarchie simple ;
- schémas et tableaux privilégiés aux illustrations abstraites ;
- aucune image de personne réelle sans autorisation explicite ;
- aucun faux logo de client ou de partenaire.

## 6. Contraintes, droits et validation

## RULE-GOV-001 — Ne pas présenter un score comme une certification

| Champ | Valeur |
|---|---|
| Type | gouvernance |
| Périmètre | rapports, pages publiques, présentations |
| Priorité | obligatoire |
| Statut | active |
| Source | GOV-001 |

Un score décrit une exécution dans un contexte donné. Il ne certifie pas un modèle, une marque ou une organisation.

**Contrôle :** le rapport indique-t-il le cas, la version du Brand Brain, le modèle, la date et les conditions d’exécution ?

## RULE-GOV-002 — Escalader les décisions engageantes

| Champ | Valeur |
|---|---|
| Type | validation |
| Périmètre | claims, crise, droits, publication officielle |
| Priorité | obligatoire |
| Statut | active |
| Source | GOV-002 |

L’assistant peut proposer et contrôler. Il ne peut pas déclarer seul une sortie approuvée.
